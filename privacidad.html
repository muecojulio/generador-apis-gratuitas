Política de privacidad

Este taller es un proyecto de código abierto que publica APIs dentro de un repositorio. La regla de oro: cuantos menos datos, mejor. No hay cuentas, no hay cookies de seguimiento, no hay analítica y no se pide ningún dato personal para usar la página.

Última actualización: 23 de octubre de 2026.

1. Quién es el responsable

El proyecto generador-apis-gratuitas se mantiene en GitHub. Si despliegas tu propia copia en Vercel, tú eres el responsable del tratamiento de esa instalación y debes adaptar este texto a tu caso. Para la instancia pública de demostración, el contacto es el repositorio (issues) y la dirección de seguridad indicada en SECURITY.md.

2. Qué datos se tratan

  • Lo que escribes al crear una API. El nombre de la ruta y la descripción (tablas, campos y reglas). Se envían a GitHub Actions para generar el plano y a un proveedor de IA gratuito. No escribas datos personales, contraseñas ni información confidencial en la descripción.
  • Los datos de las APIs publicadas. Viven en archivos data/<api>.json dentro del repositorio. Si el repositorio es público, esos datos también lo son. El taller no está pensado para información personal sensible.
  • Tokens de acceso. Se generan en tu navegador y solo se guarda su huella SHA-256 (64 caracteres). El token en claro se muestra una vez y no se envía al repositorio. Si activas «Guardar en esta pestaña» en la documentación, se guarda en el localStorage de tu navegador; no viaja a ningún servidor.
  • Datos técnicos mínimos. Como cualquier sitio, Vercel registra la petición (IP, fecha, ruta y agente de usuario) para servirla y proteger el servicio. No los usamos para perfiles publicitarios ni los cruzamos con otras fuentes. Los contadores de cupo del taller son en memoria y se olvidan en minutos.
  • Lo que no se recoge. No hay registro de usuarios, ni correo, ni teléfono, ni cookies de analítica, ni píxeles de redes sociales, ni fingerprinting.

3. Para qué se usan

Solo para prestar el servicio: generar el plano de tu API, guardarlo en el repositorio, publicarlo, documentarlo y proteger el taller del abuso. La base legal es tu consentimiento al enviar el formulario y el interés legítimo en mantener el servicio seguro y disponible. No hay perfilado, ni decisiones automatizadas con efectos legales, ni venta de datos.

4. Terceros que intervienen

Servicio Qué recibe Para qué
GitHub Nombre y descripción de la API; contenido de los datos Repositorio y ejecución del flujo de creación
Vercel Peticiones HTTP (IP, fecha, ruta, agente) Alojamiento y funciones
Modelos de IA gratuitos La descripción que escribes (LLM7, Kilo, OVHcloud, Pollinations o el que tenga clave configurada) Convertir la descripción en un plano JSON
Fuentes públicas sin clave Solo el valor de un campo pais, moneda o ciudad Normalizar ese valor (REST Countries, Frankfurter, Open-Meteo)
GitHub (public-apis) Nada tuyo: solo se lee su catálogo público de APIs Mostrar ideas de APIs sin clave

Cada servicio tiene su propia política de privacidad y puede estar fuera de tu país. Al usar el formulario aceptas que la descripción se procese en esos servicios. Si no quieres compartirla, puedes generar la API ejecutando el taller en tu computadora con GENERADOR_SIN_IA=1 npm run disenar, que no llama a ningún modelo externo.

5. Cookies y almacenamiento local

No se usan cookies. El navegador solo guarda, si tú lo pides, el token de una API en localStorage de la vista de documentación. Puedes borrarlo con el botón «Borrar» de esa misma vista o limpiando los datos del sitio.

6. Cuánto tiempo se conserva

Los planos y los datos se conservan mientras existan en el repositorio. Si una API define retencionDias, los registros más antiguos se ocultan y se borran en la siguiente escritura. Al eliminar la carpeta de la API y los datos, desaparecen del sitio en el siguiente despliegue. Los contadores de cupo en memoria se olvidan solos y los registros de Vercel siguen su propio periodo de retención.

7. Tus derechos

Puedes solicitar acceso, rectificación, cancelación, oposición y portabilidad de tus datos, y retirar tu consentimiento en cualquier momento. Para ejercerlos, abre un issue en el repositorio indicando la API afectada. Como los datos son públicos, también puedes corregirlos o borrarlos tú mismo en el repositorio. Si consideras que no se ha atendido bien tu solicitud, puedes acudir a tu autoridad de protección de datos (por ejemplo, el INAI en México o la AEPD en España).

8. Seguridad

  • Todo el sitio viaja por HTTPS con HSTS y cabeceras de seguridad (CSP, nosniff, sin frames).
  • Los tokens solo se guardan como huella SHA-256 y se comparan en tiempo constante.
  • Hay límites de tamaño de cuerpo, de registros, de peticiones y bloqueo tras intentos fallidos.
  • Las dependencias son mínimas y se revisan con npm audit en cada cambio.
  • No se acepta ejecutar código generado por IA: solo se interpreta un plano de datos validado.

¿Encuentras una vulnerabilidad? No la publiques con datos reales: usa el aviso privado descrito en SECURITY.md.

9. Menores y cambios

El taller no está dirigido a menores de 14 años y no solicita datos de menores. Si cambia esta política, se actualizará esta página y la fecha de arriba. Los cambios importantes se anunciarán en el repositorio.
