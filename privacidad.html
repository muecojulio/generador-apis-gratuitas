Política de privacidad y seguridad

Este taller es un proyecto de código abierto que diseña, documenta y publica APIs REST dentro de un repositorio de GitHub. La regla de oro es minimización estricta de datos: no hay cuentas de usuario, no hay cookies, no hay píxeles de seguimiento, no hay analítica comercial y las tipografías se sirven desde el propio dominio para no filtrar tu IP a CDNs de terceros.

🍪 0 Cookies · 0 Rastreadores 🔐 Tokens SHA-256 generados en tu navegador 🛡️ CSP estricta · HSTS · Anti-fuerza bruta ⚡ Caché e índices efímeros en memoria

Última actualización: 25 de octubre de 2026 · Versión en el repositorio: PRIVACY.md y SECURITY.md.

1. Quién es el responsable

El código fuente de generador-apis-gratuitas se mantiene públicamente en GitHub. Si despliegas tu propia copia en Vercel y GitHub, tú eres el responsable del tratamiento de esa instalación. Para la instancia pública de demostración, el punto de contacto son los issues del repositorio y el buzón de seguridad indicado en /.well-known/security.txt.

2. Finalidad y base legal

Tratamos únicamente los datos necesarios para generar el plano de tu API, guardarlo en el repositorio, servir y filtrar sus registros mediante índices en memoria, documentarlo en OpenAPI 3.0.3 y proteger el servicio frente a abusos. La base legal es tu consentimiento al enviar el formulario y el interés legítimo en mantener la seguridad y disponibilidad del taller. Nunca vendemos datos ni elaboramos perfiles.

3. Qué datos se tratan y dónde viven

  • Lo que escribes al diseñar una API. El identificador de ruta (slug), la descripción de recursos y campos, los límites de tamaño/retención y la huella opcional de token se envían a GitHub Actions para construir api/<nombre>/spec.json. No incluyas datos personales reales, contraseñas ni secretos empresariales en la descripción ni en los ejemplos.
  • Los registros de las APIs publicadas. Se guardan en data/<api>.json dentro del repositorio de GitHub y se indexan temporalmente en la memoria RAM de la función serverless (caché de lectura de 8 s, índice primario/secundario/trigramas de 60 s y respaldo de hasta 1 h ante caídas de red). Si el repositorio es público, esos archivos y su historial Git son públicos.
  • Tokens de acceso (SHA-256). Se generan localmente en tu navegador con crypto.getRandomValues. Al crear la API solo se envía su huella SHA-256 de 64 caracteres hexadecimales; el token en claro nunca se almacena en el repositorio y se verifica en tiempo constante (crypto.timingSafeEqual).
  • Preferencias locales en tu navegador (localStorage). No usamos cookies. Tu navegador solo guarda en localStorage la paleta visual elegida (taller_tema) y, si tú lo escribes en /docs, el token de prueba de cada API (taller_token_<api>). Puedes borrarlos en cualquier momento desde las herramientas de tu navegador.
  • Contadores técnicos anti-abuso. Para frenar bots y fuerza bruta, la instancia mantiene contadores efímeros en memoria por IP normalizada (1 minuto para escrituras y fallos de token; 1 hora para creación de APIs) que se descartan automáticamente al expirar la ventana.

5. Retención y borrado

Puedes borrar cualquier registro en tiempo real con DELETE /api/<api>/<recurso>/{id}. Además, si una API define retencionDias (1 a 3650 días), los registros vencidos dejan de servirse de inmediato y se purgan del archivo en la siguiente escritura.

6. Seguridad activa

Todas las respuestas incluyen CSP, HSTS, nosniff y Referrer-Policy: no-referrer. Las entradas JSON se sanean frente a polución de prototipos (__proto__) y bytes nulos, y las escrituras nunca pisan datos si GitHub no responde.

7. Tus derechos (RGPD / ARCO)

Puedes ejercer tus derechos de acceso, rectificación, cancelación/supresión y oposición abriendo un issue en GitHub o reportando de forma privada según SECURITY.md.
